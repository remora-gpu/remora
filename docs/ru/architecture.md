# Архитектура

Remora реализует **удалённый вызов CUDA API** (API remoting). Клиентский процесс загружает замены CUDA-библиотек от Remora. Каждый вызов сериализуется и исполняется воркером на GPU-сервере, где стоит настоящий драйвер NVIDIA.

```
 Клиент (Linux/Windows, без драйвера NVIDIA)          Сервер (Linux/Windows, драйвер NVIDIA)
 ┌──────────────────────────────────────────┐        ┌──────────────────────────────────────┐
 │ Приложение (PyTorch, llama.cpp, .cu ...)  │        │ remora-server (демон / служба)       │
 │   │ libcudart / cuBLAS / cuDNN ...        │        │   ├─ auth, сессии, планировщик, квоты│
 │   ▼                                       │        │   └─ remora-worker на каждого клиента│
 │ remora-shim: libcuda.so.1 / nvcuda.dll,   │протокол│        ├─ диспетчер (сгенерирован)   │
 │   libnvidia-ml, libcublas*, libcudnn* ... │◄──────►│        ├─ кэш модулей (по хэшу)      │
 │   ├─ заглушки API (сгенерированы)         │ TCP /  │        └─ настоящий libcuda + либы   │
 │   ├─ батчинг async, локальные кэши        │ QUIC / │                                      │
 │   └─ транспорт + TLS                      │ SHM /  │ /metrics, веб-панель, аудит          │
 └──────────────────────────────────────────┘ RDMA   └──────────────────────────────────────┘
                     ▲                                               ▲
                     └──── remora-coordinator (опц.): реестр, выдача GPU, RBAC, relay ───────────┘
```

## Уровни перехвата
- **CUDA Driver API** (`libcuda.so.1`, `nvcuda.dll`) — это ядро. Всё, что выше, работает через него: CUDA Runtime (статический или динамический), PTX JIT, аллокаторы фреймворков. Это включает `cuGetProcAddress` и недокументированные export tables, которыми пользуется `cudart`.
- **CUDA-библиотеки** удалённо вызываются **целиком**: cuBLAS/cuBLASLt, cuDNN, cuFFT, cuSPARSE, cuSOLVER, cuRAND, NVRTC, nvJitLink, NVML, NCCL, cuTENSOR, NPP. Переслать один `cublasGemmEx` гораздо дешевле, чем десятки вызовов драйвера, которые он делает внутри. К тому же эти библиотеки используют приватные точки входа драйвера.

## Компоненты
| Крейт | Роль |
|---|---|
| `remora-codegen` | libclang → IR → аннотации (TOML: направление указателей, размеры буферов, sync/async, типы хэндлов) → клиентские заглушки, серверные диспетчеры, кодеки, трейсинг, таблицы покрытия |
| `remora-proto` | Формат фреймов, кодек, версии, handshake. Спецификация: [Сетевой протокол](./protocol) |
| `remora-transport` | Trait `Transport` с реализациями TCP, QUIC, shared memory и RDMA |
| `remora-shim` | `cdylib` с точными именами символов (и версиями символов на Linux) библиотек NVIDIA |
| `remora-server` | Демон или служба Windows: аутентификация, сессии, планирование, квоты, метрики |
| `remora-worker` | Отдельный процесс на каждую сессию клиента (опционально в песочнице), владеет CUDA-контекстами этого клиента |
| `remora-coordinator` | Опционально: реестр серверов, выдача GPU, учёт, RBAC/OIDC, NAT relay, HA |
| `remora-cli` | `remora run / server / doctor / bench / trace / top / pair` |
| `remora-sdk` | API на Rust, C и Python для программного управления сессиями |

## Ключевые решения
- **Везде Rust**, C ABI только на границе экспортируемых символов. Внутри чужого процесса shim не использует async-рантайм; серверы используют tokio.
- **Генерация вместо ручного кода.** Сотни функций API генерируются из заголовков и аннотаций. Вручную пишется только сложное: модули, графы, export tables, виртуальная и managed память.
- **В репозитории нет файлов NVIDIA.** Заголовки при генерации берутся из локально установленного CUDA Toolkit. В репозиторий коммитятся только аннотации и сгенерированные описания сигнатур.
- **Асинхронность сохраняется.** Вызовы, асинхронные в CUDA (запуски, async-копии, запись событий), отправляются без ожидания ответа и батчатся. Ошибки проявляются при следующем синхронизирующем вызове — ровно как по спецификации CUDA.
- **Локальные кэши.** Свойства устройств, атрибуты и метаданные функций запрашиваются один раз за сессию. Модули загружаются на сервер один раз; ключ кэша — хэш содержимого.
- **Сервер не доверяет клиенту.** Каждый хэндл, длина и указатель на память устройства проверяются по таблицам сессии.
- **Процесс на клиента.** Упавший или вредоносный клиент не затрагивает остальных. Квоты и песочница применяются к каждому воркеру.

## Платформы
Клиенты и серверы работают на Linux (x86_64, aarch64) и Windows 10/11 x64 в любых сочетаниях. Генератор кода сводит различия ABI (LLP64 `long`, выравнивание структур, `HANDLE` против файловых дескрипторов) к платформонезависимому сетевому представлению. macOS не поддерживается.
